Gross, discount, net. The discount ladder — 50u→5%, 200u→10%, 500u→15% — lives inside the contract. The client cannot pick its own discount. One invoice covers every planter in the basket.
4Plant a Tree60s
Switch identity → Lakshmi Gowda → “📍 Use my GPS” (or “Generate sample proof”) → Submit planting proof
What goes on the ledger is the SHA-256 of the photo bytes and of the geo payload — not the photo. Token GT-000010 created, awaiting two endorsements. Nobody mints alone.
5Verification60s
Endorse as Dr. S. Raghavan (Forest Dept) → endorse as Nikhil Kapoor (Auditor) → flips to VERIFIED
One of two. The contract blocks the same reviewer endorsing twice, so one person cannot manufacture quorum. The reviewer sees the GPS accuracy radius before approving — the seeded example shows a rejection at 320 m.
6Ledger Explorer60s
Expand the top block
Each block carries its previous hash, Merkle root over transaction hashes, and the ordering service's signature. Expanding shows every transaction, its payload hash, and which org endorsed it. Do not rush this slide.
7The tamper test90s
“⚠ Tamper with last block” → card turns red → “↺ Restore chain”
“Now the part most projects claim and cannot demonstrate. I am going to tamper with the last block.” The verifier recomputed every hash from scratch and names the exact block and what no longer matches. Nobody changes history quietly — they only get caught. Then it restores by re-signing, so the examiner can repeat it.
8Leaderboard45s
The leaderboard is a query, not a stored score — computed from ledger state, so a planter cannot inflate their own carbon number. Every dashboard number is read from the ledger, not typed in.

One line for each hard question

  • "Real Fabric or simulation?" — Real Fabric v2.5 TS chaincode in chaincode/src/contract.ts. The business logic has no platform imports; each host supplies its own adapter. The demo ran on a Cloudflare Durable Object — a real ordering-and-commit host that needs no Docker. Same contract, unchanged, on Fabric.
  • "Why two endorsements?" — One approver is the trust problem. Two independent orgs must sign, and the contract enforces no double endorsement. That rule is in the chaincode, not the UI.
  • "Can a planter fake it?" — Same photo twice is bound to a geo-hash and a distinct token id; the reviewer sees the GPS radius; and they still need two orgs they do not control.
  • "How do I know the numbers are real?" — They're read out of ledger state by the same read models the HTTP API exposes. I can show you the endpoint. Nothing is typed in by hand.
